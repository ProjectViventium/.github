# Contributing

## Before You Start

- Open an issue before large changes so scope and direction are aligned.
- Keep pull requests focused. Small, reviewable changes move faster and reduce regressions.
- Do not include secrets, credentials, personal data, customer data, or machine-local artifacts in commits.

## Pull Requests

- Use a branch and pull request for changes unless you are an organization admin handling urgent maintenance.
- Include tests or a clear verification note when behavior changes.
- Update documentation when product behavior, developer workflow, or public usage changes.
- Keep CI and security checks green before requesting review.

## Security

If you find a vulnerability, do not disclose it publicly. Use the repository's private vulnerability reporting flow described in `SECURITY.md`.
